# 多人協作地圖功能實作計畫

這個計畫涵蓋了您要求的所有高級地圖協作與繪圖功能。因為功能龐大且需要後端支援（如多人實時同步、留言、專案儲存、權限管理等），我們將採用 **Firebase (Firestore + Authentication)** 作為後端解決方案，並搭配 **Fabric.js** 來處理複雜的畫布與圖形操作。

> [!IMPORTANT]
> **Firebase 配置需求**
> 本專案需要 Firebase 的實時資料庫與身分驗證服務。若您同意此計畫，我將會在程式碼中預留 Firebase 的設定區塊，請您準備好 Firebase 的設定檔 (Config) 並啟用「Google 登入」與「Firestore 資料庫」。

## 核心功能架構

### 1. 繪圖與圖形操作 (Fabric.js + Leaflet)
為了解決地圖上的複雜繪圖需求（畫圖、圖片、形狀、移動、縮放模式），我們將在 Leaflet 地圖上方覆蓋一層透明的 Fabric.js 畫布。
- **繪圖模式**：支援自由繪圖、插入圖片、插入幾何形狀。
- **縮放與變形**：Fabric.js 原生支援形狀/圖片的拉伸與等比例縮放（按住 Ctrl 等比例縮放）。
- **畫布同步**：當 Leaflet 地圖平移或縮放時，自動計算並更新 Fabric.js 畫布中所有物件的座標與縮放比例。
- **「切割」與「拉伸」縮放模式切換**：我們將提供一個開關，決定圖片在縮放時是改變外框（切割/Crop）還是真實變形（拉伸/Stretch）。

### 2. 專案與圖層系統 (Projects & Layers)
- **專案綁定圖層**：使用者在建立專案時，專案會與當前的地圖圖層（普通地圖、衛星影像、混合地圖）綁定。當其他人切換圖層時，只會顯示該圖層專屬的專案。
- **專案顯示**：每個專案會在地圖上顯示為一個標記（使用創建者的頭像）。
- **專案資訊**：點擊標記會彈出視窗，顯示：專案名稱、介紹、創建者名稱/頭像、批准狀態。

### 3. 多人即時同步與資料庫 (Firebase Firestore)
- **`users` 集合**：儲存使用者的 UID、名稱、頭像、角色 (admin/user)。
- **`projects` 集合**：儲存專案的 ID、名稱、介紹、圖層 ID、創建者資訊、狀態 (pending/approved)、以及 Fabric.js 的畫布 JSON 序列化資料。
- **`comments` 集合**：儲存使用者對特定專案的留言。
- **實時更新**：利用 Firestore 的 `onSnapshot`，只要有人建立或修改專案、留下評論，所有在線上的使用者都能瞬間看到變化。

### 4. 權限與審核系統 (Admin & Approvals)
- **管理員特權**：管理員創建的專案會自動標記為 `approved`（已批准），且專案面板會特別標示「管理員創建」。
- **審核機制**：一般使用者創建的專案預設為 `pending`（待審核）。管理員可以在專案的彈出視窗中點擊「批准」按鈕。
- **過濾器**：在畫面上方提供過濾器選單：
  1. 顯示全部
  2. 只顯示已批准
  3. 只顯示未批准
  4. 都不顯示

## 驗證計畫
- 開啟網頁後，驗證是否能透過 Google 登入。
- 驗證能否在地圖上繪製圖形、上傳圖片，並隨地圖縮放而正確移動。
- 驗證專案儲存後，其他人是否能立刻在地圖上看到頭像標記。
- 驗證管理員審核與過濾器功能是否正常運作。
