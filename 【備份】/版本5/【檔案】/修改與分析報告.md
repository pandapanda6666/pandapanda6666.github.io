# 程式碼修改與分析報告

## 1. 練習模式調整
- **分析**：目前卡片擁有點擊翻面的機制，且缺乏跳過機制。
- **計畫**：
  - 移除卡片點擊翻面的事件 (\onclick="flipCard()"\) 與相關 CSS 效果。
  - 調整 \.mc-btn\ 的寬度、高度與字體大小，讓選項更清楚易點。
  - 在卡片與選項下方新增一個小型的「⏭️ 跳過」按鈕，點擊後停止目前語音並直接進入下一題。

## 2. 填空遊戲虛擬鍵盤優化
- **分析**：原先新增的虛擬鍵盤 (\#virtualKeyboard\) 尺寸過小，且按鈕佈局需要調整。
- **計畫**：
  - 加大 \.vk-key\ 等按鈕的 \ont-size\、\padding\ 與 \min-width\，適合點擊。
  - 重新排列最後一排按鈕的 HTML，將 \Enter\ 移至最左側，\刪除 (Backspace)\ 移至最右側。

## 3. 顯示與音效的平衡及打斷機制
- **分析**：原先使用者在題目語音播放中若提早作答，題目語音可能繼續與結果音效重疊。且切換下一題的時機與音效長度脫鉤。
- **計畫**：
  - 在作答（點擊選項或送出填空）時，立即呼叫中斷語音的函式（暫停 \currentAudio\ 及 \speechSynthesis.cancel()\）。
  - 將 \
extCard()\ 和 \
extSpellWord()\ 的延遲時間 (\setTimeout\) 對齊成功與失敗音效的播放長度，確保音效播完才切換畫面。

## 4. 防範作答後的短暫修改漏洞
- **分析**：在答錯或答對後的等待跳轉期間 (\setTimeout\)，因為沒有徹底鎖死介面，導致玩家還能點擊其他按鈕或繼續打字修改。
- **計畫**：
  - 引入全域的 \isProcessing\ 變數，當判斷作答後即設為 \	rue\。
  - 在練習模式選項點擊、填空模式鍵盤輸入/點擊時，一律先檢查 \isProcessing\。若為 \	rue\ 則直接拒絕任何操作，直到下一題畫面重置完畢。
